# Dogfooding through an actual user task

## Experience is the evidence (2026-08-13)

A source-only account of what a user would experience cannot establish whether
the system is useful. `me-human` asks the session to pursue a concrete goal
through the allowed surface and report the friction encountered. It supplies
an end-user perspective without denying assistant identity.

The user supplies the system, entry point, goal and allowed surfaces. The skill
stays portable across apps, CLIs, plugins and other workflows instead of owning
a browser or runtime harness. QA coverage and focused correctness proof remain
with their respective skills.

## Authority stays with the task

Try available controls and supported paths before asking questions the system
can answer. A blocking bug permits a correction only under existing repair
authority; dogfooding itself does not authorize implementation. Report attempted
corrections and their outcomes, and continue authorized independent work.
Concrete sandbox or access failures follow the host's escalation rules. An app
bug alone does not justify privilege escalation.

Stop at an unresolved scope or capability boundary with the observed failure,
attempts and missing decision. The former unconditional retry and local-edit
rules are superseded by this authority boundary. The result is a concise account
of the task, friction, recommendations and next steps, not an imagined experience.
