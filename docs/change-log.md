# Release Notes

Release notes for the shipped plugins (`workbench` and `toolkit`) newest
first, one section per released version. Strictly plugin releases: repo-only
work (structure, docs, tooling) lives in `docs/decisions/` and the git log,
not here. **Bounded:** at most 15 release sections: adding one past the cap
deletes the oldest (git history keeps everything). Sections from before the
2026-08-11 plugin split (`reviewers`, pre-split `toolkit`) were dropped in the
2026-08-12 reformat.

## workbench 0.64.0: 2026-11-09

- **Reconcile lanes every owner turn and drain ready work.** `epic-orchestration` starts each owner turn by comparing every active lane with the ledger, so an unrelayed report is validated and a silent lane is held for the operator. The reply that ends a turn now accounts for every open workset as active, dispatched or held, and carries the closing audit's brief, the closure proposal or a hold when none is open. Hold lines gain `since`, `rechecked` and `operator action` slots, and the slot takes any hold the operator releases. ([decision](decisions/epic-orchestration.md#the-owner-reconciles-lanes-drains-ready-work-and-closes-lanes-out-2026-11-09))
- **Close lanes out and gate closure on follow-ups.** One closeout pointer releases an implementation or audit lane whose delivery merged, whose audit was accepted, or whose remaining work was withdrawn, and names the lane's reporting skill. Closure is proposed only after every follow-up and debt item has the operator's disposition. The label, pointer and return order moved into the entrypoint; journey planning, tracker mapping, delivery detail and the closing audit moved to references. ([decision](decisions/epic-orchestration.md#the-owner-reconciles-lanes-drains-ready-work-and-closes-lanes-out-2026-11-09))
- **Make lane handbacks relayable.** `epic-implementation` ends every final handback with the fenced report block and saves the same block when the contract asks, answers an acknowledge-only dispatch in one line, and puts an approval only the operator can grant in `NEXT STEP` with `operator` as owner instead of opening a question dialog. The lane reads the completion round's inputs from the delivery reference. ([decision](decisions/epic-implementation.md#the-lane-reads-the-completion-rounds-inputs-2026-11-09))
- **Dispatch reviewers with labelled lines.** Each reviewer agent's description now names the lines a parent dispatches it with, and `code-quality-review` no longer asks the parent to paste the diff and file contents. The dispatching session's half of every correction round moved into `receiving-code-review`, which sessions load. ([decision](decisions/code-quality-review.md#the-dispatch-is-pointers-agent-descriptions-name-them-2026-11-09))
- **Send a later delta only to the reviewers whose ground it changes.** A reviewer that passed gets a follow-up when the delta changes production logic or tests (test quality), observable behavior or wiring (contract), or structure beyond its findings' lines (code quality). An applied advisory never returns to the reviewer that raised it. The follow-up message is a fixed set of lines, with optional ones for uncovered mutation scope, forwarded results, a waiver, a hold decision or a user request. ([decision](decisions/bounded-correction-review.md#a-passed-reviewer-sees-a-later-delta-only-when-its-ground-changes-2026-11-09))
- **Open every review report with the verdict.** Code-quality, test-quality, contract and spec reviews now start each round's report with the verdict line, a report without it reads as `ISSUES_FOUND`, and a dispatch's own severity words are mapped in the body. ([decision](decisions/test-shape-and-mutation-review.md#dispatch-lines-and-the-verdict-line-2026-11-09))
- **Let the trimmer commit only on the dispatch's terms.** `comment-trimmer` makes its comment-only commit when the dispatch carries `Commit subject:`, every file it edited was clean and the index holds no one else's staged work; otherwise it reports `Commit: not made` with the reason. It runs the documented formatter over the files it edited and accepts a re-wrap only inside a hunk it trimmed. ([decision](decisions/trim-comments.md#the-trimmer-commits-when-the-dispatch-gives-a-subject-2026-11-09))
- **Define mutation outcomes for restrictions, copies and busy hosts.** A dispatch that limits the mutation lane without citing a waiver is recorded as `blocked: dispatch restriction`, and wait or budget numbers in a dispatch are not applied. The reviewer removes its disposable copy on `PASS` and otherwise reports its path and kind for the dispatching session to remove. A busy host with nothing run stays `blocked: host busy` and gets one follow-up before it goes to the user. The slot helper skips listings and no longer treats `cargo mutants -V` as one. ([decision](decisions/mutation-scope-and-budget.md#restrictions-copies-busy-hosts-and-other-hosts-2026-11-09))
- **Pin code-quality and spec review to Opus 5.5 on Claude Code.** `code-quality-reviewer` and `spec-reviewer` run on `claude-opus-5-5` at `xhigh` on Claude Code whatever the parent runs. Codex and other harnesses keep the parent's model and effort. ([decision](decisions/code-quality-review.md#claude-code-pins-opus-55-at-xhigh-2026-11-09))
- **Bring the model-reference table and notes back into agreement.** `model-reference` corrects reading notes that contradicted the re-graded table, places the `code` axis in the priority order, adds an `effort` column and an ungraded `fable-5.2` row, and defines what a calibrated row records. Escalation now climbs effort before tier: a self-check first, then one effort level below `high`, or the next tier at a lower effort at `high` or above. ([decision](decisions/model-reference.md#table-and-notes-agree-again-effort-is-recorded-escalation-climbs-effort-first-2026-11-09))
- **Give the CI watcher a dispatch block and a way to resume.** `fix-ci` dispatches `ci-watcher` with seven required slots, sizes the deadline from the repository's last successful runs (capped at sixty minutes), and uses literal wait values on Codex. A watch that ended `pending`, or blocked on failed reads, continues once under a `Resume` dispatch with a new deadline; a second read block is reported. A flake rerun gets its own state file. ([decision](decisions/fix-ci.md#stalled-watches-resume-and-dispatches-carry-labelled-inputs-2026-11-09))
- **Name verification at the landing gate and keep evidence across unrelated merges.** `file-pr`'s gate now names `verification-before-completion` and its three operative rules. A clean merge of target commits keeps local check evidence only when no incoming path is one the branch changes, is read by an affected check, or depends on what the branch changes; anything else reruns the checks. ([decision](decisions/file-pr.md#unaffected-clean-merges-keep-their-check-evidence-2026-11-09))
- **Keep the orientation out of dispatched subagents.** `using-workbench`'s description excludes a subagent dispatched for a specific task, routes a written spec or plan to `spec-reviewer`, and states the disposable-checkout rule for pre-fix comparisons in its verification summary. ([decision](decisions/skill-descriptions-state-when-not-what.md#using-workbenchs-description-excludes-dispatched-subagents-2026-11-09))
- **Check for unwritable directories before removing a worktree.** `workspace-cleanup` runs a check for directories the user cannot write before a non-force `git worktree remove`, holds the entry on any hit and asks for the permission change, since Git drops the registration even when it cannot delete the files. ([decision](decisions/workspace-cleanup.md#read-only-directories-are-checked-before-worktree-removal-2026-11-09))
- **Ask open questions before offering options.** `brainstorming` asks what the user wants the thing for as a plain open question, says what each answer would change, and drops weak approaches before proposing two or three, or one with the reason the others do not fit. ([decision](decisions/skill-wording-hardening.md#brainstorming-takes-three-question-techniques-from-upstream-v702-2026-11-09))
- **List claim-check's verdicts and widen audit's static tier.** `claim-check` lists its verdict buckets in the spec. `audit`'s static review covers read-only code audits, checks reader claims the verdict rests on firsthand, and asks the sizing question only when tiers differ in cost or modality. ([decision](decisions/claim-check.md#the-verdict-buckets-are-listed-in-the-spec-2026-11-09))
- **Retire `session-messaging`.** The skill, its usage page and its decision history moved to `attic/deprecated/skills/session-messaging/` and left the catalogs and manifests. ([decision](decisions/workbench-operator-decisions.md#session-messaging-retired-2026-11-09))

## toolkit 0.23.0: 2026-11-09

- **Add `recall`.** A user-invoked, read-only skill rebuilds recent working context from earlier sessions in the workspace across Claude Code, Codex, Muse and Cursor, checks each thread against live `git` and `gh` state, and returns a capsule, status-tagged threads, recurring problems and one next move. ([decision](decisions/recall.md#adopted-from-pstack-as-an-explicit-entry-point-2026-11-09))
- **Tighten what a `ketchup` update can claim.** `ketchup` lists every waiting item, checks shown numbers against their source, keeps each line true read alone, and asks a decision shared by several items once with a line per item, riskiest first. ([decision](decisions/ketchup.md#accuracy-rules-from-the-later-upstream-revision-2026-11-09))
- **Write the decision before a benchmark comparison.** `benchmark-checklist` has a comparison state in advance the result that would change the decision and the noise floor it expects. ([decision](decisions/benchmark-checklist.md#the-decision-is-written-before-the-run-2026-11-09))
- **Align the architecture survey's card and add an authorized-implementation exit.** `improve-codebase-architecture` and its report contract use one field vocabulary, recurring-mistake cards gain a prevention slot, and an invocation that already authorizes implementation records a decision per candidate instead of asking which to explore. ([decision](decisions/mattpocock-skills.md#one-card-vocabulary-and-an-exit-for-authorized-implementation-2026-11-09))
- **Fix `get-pr-comments`' inline-comment fetch and add thread state.** The pull request number comes from the first step instead of a placeholder `gh` does not fill, resolved and outdated threads are read from GraphQL, and the description states only when to use the skill. ([decision](decisions/get-pr-comments.md#a-number-gh-does-not-fill-thread-state-and-a-trigger-only-description-2026-11-09))
- **Scope `web-demo-video` to recorded walkthroughs.** Its description no longer claims screenshot-only requests, and the setup-authority condition sits in the entrypoint. ([decision](decisions/web-demo-video.md#walkthroughs-only-and-setup-authority-in-the-entrypoint-2026-11-09))
- **Name the substitute when an audit tool is missing.** `dependency-audit` allows a substitute advisory source only when the report names it and what stayed unchecked. ([decision](decisions/dependency-audit.md#a-named-substitute-for-a-missing-audit-tool-2026-11-09))

## workbench 0.63.0: 2026-11-07

- **Queue mutation campaigns host-wide.** `test-quality-review` now launches every Stryker and cargo-mutants run through a bundled `scripts/mutation-slot.mjs`, which runs one campaign at a time per host in arrival order, recovers locks left by crashed reviewers, still waits for campaigns started without it, and keeps working where a sandbox refuses `ps`. Its summary line gives the seconds waited, the queue mode and whether the process listing could see other sessions, for the Mutation run line. ([decision](decisions/mutation-scope-and-budget.md#queued-campaigns-two-reviewers-per-session-real-dependency-directories-2026-11-06))
- **At most two test-quality reviewers per session.** `test-quality-review` and `using-workbench` cap concurrent test-quality reviewers at two, since their campaigns share one slot per host; other review stages stay unlimited. ([decision](decisions/mutation-scope-and-budget.md#queued-campaigns-two-reviewers-per-session-real-dependency-directories-2026-11-06))
- **Give Stryker a real `node_modules`.** The mutation rubric now replaces a linked `node_modules` in the disposable copy with a real directory of links before the first dry run, because Stryker skips a symlinked one and the sandbox then cannot load dependencies. ([decision](decisions/mutation-scope-and-budget.md#queued-campaigns-two-reviewers-per-session-real-dependency-directories-2026-11-06))

## toolkit 0.22.0: 2026-11-04

- **Ship the session-transcript rule on every host.** `adopt-global-rules` adds a `session-transcripts` core rule to Claude Code, Codex and Muse, so sessions never suggest, delete, move, compress or truncate agent session history or shorten a host's retention setting. ([decision](decisions/adopt-global-rules.md#session-transcripts-ship-as-a-core-rule-2026-11-04))

A first Muse adoption replaces `~/.claude/CLAUDE.md` in Muse sessions, so the skill names what Muse would lose and the user chooses how to proceed. ([decision](decisions/adopt-global-rules.md#session-transcripts-ship-as-a-core-rule-2026-11-04))

## workbench 0.62.0: 2026-11-04

- **Open reports with holds that stop several lanes.** `epic-orchestration` owner returns gain a required **Active holds** slot ahead of **Progress**, and every other operator reply carries it too. Each line names what is stopped, who ordered it, the source's exact words and what releases it. A reading wider than those words is recorded as the epic owner's, with a request to confirm or narrow it in the same reply. ([decision](decisions/epic-orchestration.md#a-wide-hold-opens-every-report-2026-11-04))
- **Never touch session transcripts during cleanup.** `workspace-cleanup` leaves agent session history out of inventories, totals, batches, estimates and prevention advice. It never suggests, deletes, moves, compresses or truncates that history, never shortens a host's retention setting, and reports a storage target it cannot reach without them as a remaining gap. ([decision](decisions/workspace-cleanup.md#session-transcripts-are-never-a-candidate-2026-11-04))

## workbench 0.61.0: 2026-11-04

- **Let the Muse scope review read the whole checkout.** `scope-review` starts from named files and follows them through the reviewed checkout, under one 10-minute deadline instead of 120 seconds and 8 model steps. The packet-only runner is gone. A read or search result from a secret-bearing file or outside the checkout rejects the run and is reported to the user. ([decision](decisions/scope-review.md#checkout-reads-no-runner-2026-11-04))
- **Run Muse through the surface's own handler.** When the session's surface can start Muse itself, such as T3 Code's `delegate_task`, the review goes through it, and `muse exec` remains the route elsewhere. Native handlers may gate tools behind approvals rather than remove them, so any approval or question cancels the run as a skip. ([decision](decisions/scope-review.md#checkout-reads-no-runner-2026-11-04))
